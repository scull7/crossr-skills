1. Method

Five skills copied into subzeroplay/.agents/skills/: code-writer, ocaml-code-writer, and the three new gates. No harness wiring invented (og-04).

Each gate ran as a fresh activation with a deliberately neutral prompt. No agent was told what verdict to reach or which defects existed — otherwise the exercise proves only that agents follow instructions. Every claim an agent made was then re-verified against the source by hand. Steps A, B, C were read-only; file mtimes confirm they wrote nothing.

4. Green is not the evidence — mutation testing

A passing suite says nothing about whether the new assertions bite. Two mutations were introduced into the domain and the suite re-run. Both were caught; both were reverted byte-identical.

MutationCaughtFailure message
attendance_of_string "absent" → None Yes FAIL: attendance Absent: expected absent to round trip
| _, View, _ -> true → false Yes FAIL: Player Views an Occurrence: expected true

The second is the load-bearing one. That universal View arm had zero tests before this pass. The tester named it, the writer covered it, and the mutation proves the coverage is real. That is the full GAN loop closing on a defect nobody had written down.

5. Findings not on the prediction list

The strongest evidence that the skills are doing work rather than pattern-matching a brief: each of these was found unprompted and verified independently.

  • A dead public error constructor

    Occurrence.write_error.Blocked is unreachable. overlap has only Clear | Notice; blocks maps both to false; so Error Blocked at occurrence.ml:345 can never be returned. The one test touching it asserts it is not produced. Found by the tester, confirmed by hand. Scoresheet.Forbidden is the same shape — declared, constructed nowhere.

  • The reviewer rejected a false premise it was handed

    The brief stated as a product constraint that "store's module-level let* is Option.bind". The reviewer checked the source and refused it: there is no module-level binding at all. All 17 are function-local — one Option.bind at line 90, sixteen Result.bind. Verified. A gate that verifies its own constraints is worth more than one that obeys them.

  • The build proves the layering claim

    test/dune links domain only, and server_lib is (modes melange) feeding a melange.emit. The server library cannot be linked into a test at all, so every calculation that drifted into the store is untestable by construction. The architect and tester reached this independently.

  • Command/query entanglement is compiled in

    Every write operation returns the full page read model as its success type, so the type checker couples mutation paths to view shape. A display change breaks a write path.

  • A hardcoded fallback credential

    store.ml:39 falls back to the literal "playdev" when SEED_PASSWORD is unset. Flagged by the reviewer, confirmed present, deliberately left unfixed — out of scope for this pass and recorded here instead.

6. Honest caveats

  • @fmt is UNVERIFIED. No .ocamlformat in the repo and no ocamlformat in _opam/bin. Nothing was installed. Formatting of new code is hand-matched, not machine-proven.
  • Types sit above the first let, but below an FFI block. store.ml:4–11 are Melange external declarations, and type env/type mkdir_opts at lines 1–2 exist solely to type them. The reviewer's rule names external as a value binding, so this is a defensible carve-out rather than a clean pass.
  • One tester imprecision. It quoted blocks as | _ -> false when the source reads | Clear | Notice -> false — exhaustive, not a catch-all. The conclusion holds; the quote was not literal.
  • Step D was scoped, not complete. Transactions without rollback, quadratic attendance_by_occurrence, loaded_rows re-execution, raw string roster ids, function lengths, and the seed password were all left untouched by instruction. The reviewer's list is not discharged.
  • The suite is still one let () =. fail calls exit 1, so the first break masks every later assertion. The tester called this out; restructuring it was out of scope and remains open.

7. Conclusion

The three skills change agent behaviour on real code. Each gate produced its specified verdict and format from a neutral prompt, respected its boundary — the architect named jobs and never files, the reviewer never proposed a split, the tester never wrote a test — and each surfaced defects that were not in the brief and that survived independent verification.

No skill required a fix. Nothing was recopied. The architect's standing REJECT is the correct terminal state: store.ml is still one unit doing many jobs, and no amount of line-level cleanup changes that. The seam is the next piece of work, and it belongs to a plan, not to this pass.
